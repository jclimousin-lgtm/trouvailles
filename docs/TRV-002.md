## 4. Fonctionnement de Leboncoin

`LeboncoinAdapter::search()` → `LeboncoinClient::searchPage()` (POST JSON vers `api.leboncoin.fr/finder/search`) → mapping vers `NormalizedListing` (mono-devise EUR, prix fixe uniquement). Pagination gérée (arrêt quand une page renvoie moins que `limit`, ou après `max_pages`). Erreurs gérées explicitement : 403 (Datadome, non contourné), 429, réponse vide, JSON malformé, champs `list_id`/`url` absents (annonce ignorée sans interrompre le lot).

**Vérification réelle (§17)** : tentative de recherche réelle ("velo") — **bloquée en HTTP 403**, message explicite « probable protection Datadome ». Cause précise et attendue : ce client n'implémente aucun contournement (interdit par la mission), contrairement à `lbc` qui utilise l'impersonation TLS pour passer cette même protection. Non simulé.

## 5. Fonctionnement de Vinted

`VintedAdapter::search()` → `VintedClient` établit d'abord une session (requête GET anonyme standard vers la page d'accueil, récupère le cookie `access_token_web` via `Set-Cookie`), puis interroge `GET /api/v2/catalog/items` avec ce cookie. Mapping vers `NormalizedListing` (prix fixe uniquement). Mêmes catégories d'erreurs gérées que Leboncoin (401/403, vide, malformé, champs absents).

**Vérification réelle (§17)** : tentative de recherche réelle ("robe") — **bloquée en HTTP 403**, message explicite « probable protection anti-bot ». Le mécanisme d'accès standard (sans impersonation TLS, contrairement à `vinted-api-kit`/`vinted-mcp-server`) ne suffit pas à passer la protection de Vinted en conditions réelles. Non simulé, non contourné.

## 6. Fonctionnement d'eBay

`EbayAdapter::search()` → `EbayClient` obtient un jeton OAuth2 (`client_credentials`) puis appelle `GET /buy/browse/v1/item_summary/search` (Browse API officielle, header `X-EBAY-C-MARKETPLACE-ID`). `buyingOptions` détermine `priceMechanism` (`AUCTION` → enchère, sinon prix fixe) — seule marketplace des trois pouvant produire `price_type=auction`/`evidence_type=active_auction` (§9). Erreurs gérées : échec OAuth, 429, réponse vide/malformée, champs absents.

**Vérification réelle (§17)** : **non exécutée** — aucun identifiant `EBAY_CLIENT_ID`/`EBAY_CLIENT_SECRET` disponible dans cet environnement. Échec propre et explicite (`InvalidArgumentException`), pas de secret en dur (§14), rien simulé. À exécuter dès que des identifiants développeur eBay seront fournis.

## 10. Blocages rencontrés

1. **Bug réel corrigé pendant la mission** : `ListingPersister` tentait d'écrire `asking_price`/`asking_currency` sur `listings` même quand la devise était absente, violant la contrainte `chk_listings_currency_with_price` (TRV-001-C) — détecté par le test "prix sans devise", corrigé (le prix n'est écrit ni sur `listings` ni sur `price_observations` sans devise, dans les deux cas).
2. **Anti-bot** : Leboncoin (Datadome) et Vinted (Cloudflare/protection similaire) bloquent ce client en conditions réelles (403) — attendu et documenté au §4/§5, aucune tentative de contournement.
3. **eBay** : vérification réelle impossible faute d'identifiants Browse API dans cet environnement.
